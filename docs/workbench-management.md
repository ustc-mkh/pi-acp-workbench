# 模型、用量与命名

桌面顶部的“模型设置”和“用量统计”打开独立页面。两者会先刷新本地 Pi 模型目录，再读取共享设置；不要求选择会话，不发起模型推理。翻页使用已保存数据，刷新失败时仍显示缓存并提示原因。

## 模型设置

- 按 provider 分组、搜索。勾选或取消“显示”会立即保存可见性。隐藏当前模型会保留会话的模型选择。显示当前 Pi 会话尚未提供的模型会刷新该会话的模型列表，也可点击“刷新模型配置”手动刷新。发送控件使用会话通过 ACP 提供的模型。
- 默认价格和 context 来自 Pi 本地模型目录。匹配时忽略渠道前缀、大小写、空格、连字符和下划线，保留小数版本、日期和变体后缀；宿主分别选择价格和 context。官方目录明确标价为 0 时保留免费价格。匹配可以使用未配置供应商的目录数据，这些候选项不会增加会话可选的模型。
- 自定义价格、倍率、可见性和 context 按 Agent/模型分别保存。通过“保存”提交价格、倍率和 context；“恢复默认”清除覆盖并将倍率重置为 1。
- 四项价格分别为输入、输出、缓存读取、缓存写入，单位是 USD / 百万 token。清空全部价格使用默认值；无价格显示未定价，不当成免费。倍率允许 0–1,000,000，默认 1。
- Pi context 使用 k tokens（256 表示 256000）。清空恢复 Pi 默认值；该设置不会提高供应商的真实上下文能力。其他 Agent 不提供 Pi context 写入。

显式模型/thinking 设置先读取 provider 当前选项，清理撤下的旧选项，仅在 provider 确认后保存。失败或未知结果不更新默认偏好，也不在重连时自动重发。

## 用量统计

按模型、UTC 天/周/月或会话分组，支持日期、模型 ID、会话筛选。每页最多 10 个聚合组；总计覆盖全部筛选结果。模型按估算费用排序，会话按编号排序，周从周一开始。

统计区分输入、输出和两类缓存 token；缺失用量、缓存或价格单独提示，不补成 0。统计与模型设置使用同一套价格规则，优先取该 Agent 和模型的自定义价格，再取目录默认价格。费用按当前单价和倍率估算，修改价格会影响历史估算。

每轮和自动标题调用都有独立、可去重的用量身份。Pi 只统计本轮新增的原生记录，不回填 load/fork 继承历史。删除会话后保留已发生的用量、编号和已保存的会话名。

## 会话命名

会话具有持久编号；首条输入生成本地短标题，用户可手动命名。自动命名支持关闭、跟随当前 Pi 模型或指定 Pi 模型，默认跟随。

Pi 在首轮结果后通过独立、无工具和项目上下文的临时进程生成名称，只使用输入前 1000 个字符，不阻塞后续业务输入。手动名称优先；失败或中断不会自动重试，也不会批量改名旧会话。

## Pi context 的持久化

SQLite 保存期望配置、递增 revision 和待应用状态。宿主串行请求配套 adapter 更新 Pi profile 的 `models.json`，刷新模型目录并确认；仅在精确 revision 获得确认后标记已应用。价格和倍率只存于 SQLite。

adapter 在规范化后的文件目标上持有跨进程锁，以原子替换合并配置，保留无关字段。相邻的 `models.json.workbench-context.json` 记录数据目录所有权和 revision，拒绝旧版本覆盖、同版本冲突及另一数据目录争用 profile。

数据库和 JSON 文件不是同一事务。中断后保留待应用状态，下次明确 discovery、刷新或输入前对齐配置，不重放模型输入。外部编辑冲突需处理后重新保存。每个数据目录使用稳定、独立的 Pi profile；备份时同时保存数据库、`models.json` 和 checkpoint。

## 目录刷新

Pi 适配器分别返回可用模型和同型号候选项。一次刷新最多接收 500 个可用模型、20,000 个候选项。候选项每页最多 500 个，宿主用快照标识和下一页偏移读取后续页，收齐后在一个 SQLite 事务中更新默认值。候选项只参与匹配，刷新时保留用户覆盖。模型设置查询的字段见 [IPC v3](workbench-ipc.md)。

实现位于 `domain/management.rs`、`persistence/{management,model_context}.rs`、`app_model_context.rs`、`src/pi-context-*.ts` 和 `webview/workbench-management.ts`。
