# 工作区 Diff 与撤回

## 查看与撤回

每轮任务结束后自动展示变更卡片；滚动到历史回合时自动读取旧 Diff。展开可查看新增、修改、删除、权限及行数，单文件或总 Diff 可在编辑器打开。归档大文本按需分片加载。

“撤回本轮修改”经预检和确认后恢复轮前普通文件的内容与权限。右键该按钮可选择文件分批撤回，每批最多 256 个文件、路径总量 64 KiB。撤回不改变聊天历史、模型上下文或 Git index。

如果快照不完整、工作区有冲突或仍有重叠目录的 provider，撤回会被拒绝。多文件撤回可能部分成功，结果逐文件报告 `restored`、`uncertain` 或 `not_attempted`；未知结果不自动重试。

## 采集与存储

宿主在派发输入前采集基线，在完成、取消或 provider 退出后采集结果。基线包括轮前已有的未提交修改，不等于 Git HEAD；采集覆盖 Git 已跟踪和未被忽略的未跟踪文件，包括 shell 写入。

| 范围                          | 上限                |
| ----------------------------- | ------------------- |
| 枚举路径                      | 5000 个             |
| 单文件文本                    | 1 MiB               |
| 单次快照文本                  | 16 MiB              |
| 每轮完整文本详情 / 编辑器查看 | 4 MiB               |
| 摘要分页 / 正文分片           | 16 个文件 / 64 KiB  |
| 页面文本预览                  | 400 行 / 30000 字符 |

二进制、非 UTF-8、符号链接、特殊文件、超限、读取失败或 `.gitignore` 变化会导致部分结果。没有有效 Git worktree 时显示不可用。崩溃前未保存的最终快照不在重启后重建；Pi 自主轮次因缺少完整轮前基线，也显示不可用。

对于只在一侧快照中出现的文件，宿主用目录中的实际条目核实路径是否存在。轮前已被忽略的文件即使在本轮被强制暂存，也会保留。如果路径落在未枚举内容的目录中，或路径清单超出预算，该轮会标记为部分快照。旧版完整归档若包含缺少轮前路径证据的新增文件，仍可查看，整轮及按文件撤回均禁用。

Diff 按 `(session, turn)` 不可变保存在 SQLite `turn_diffs`；读取不启动 provider。删除会话会删除其 Diff，但不会修改工作区文件。

## 冲突保护与限制

桌面端先对选定轮次和文件调用 `validate_undo`。预检通过且工作区内没有未保存的编辑器内容时，扩展才弹出确认框。用户确认后，扩展再次检查未保存内容、工作区授权、当前会话和活动轮次，再用持久操作 ID 提交 `undo_turn`。宿主验证文件仍等于轮后内容、哈希和权限，拒绝路径越界、链接穿越、特殊权限等情况。

撤回先停止自己的 provider，再获取同目录及父子目录的排他许可；其他重叠 provider 需先释放。文件经暂存、同步和再次检查后逐个发布；多文件不是一个文件系统事务，失败后停止后续发布。

快照只表示两次采集间的净变化，可能包含手工或其他会话修改。工作区外、Git 忽略文件及外部后台程序不在保证范围内；外部编辑器或进程仍可能在检查和发布之间写入。

实现位于 `workspace_{review,reviews,gate,undo}.rs`，宿主入口为 `app_workspace.rs`，桌面端由 `src/workbench-undo.ts` 处理确认与提交，由 `webview/workbench-diff-view.ts` 管理文件选择和分页展示。
