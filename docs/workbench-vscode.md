# VS Code / browser on IPC v3

The default local build bundles `src/workbench-extension.ts` and `webview/workbench-main.ts`. These use the new `WorkbenchController` / `WorkbenchSession` / `WorkbenchClient` directly, not an ACP-shaped facade or a legacy wire adapter. The old extension/controller/wire source and old daemon crates have been removed from the production workspace. No existing service or user data was deployed, migrated or deleted.

## Local connection

Run the new host with an explicitly chosen format3 storage root:

```sh
cargo run --manifest-path rust/Cargo.toml -p pi-acp-workbenchd -- --config /absolute/path/workbench.json
```

See `examples/workbench.json`, `docs/workbench-ipc.md` and the explicit offline-only [`docs/workbench-storage.md`](workbench-storage.md) same-binary, host-lease-protected export/reset/typed Telegram GC utility. Configure **`piAcp.workbenchSocket`** to `<storage.root>/workbench.sock`; empty defaults to `~/.pi/pi-acp-workbench/workbench.sock`, matching the example root after substituting your account. Reload the extension after changing the path. There is no fallback to any old socket, service version or storage layout. An old nonempty storage directory is explicitly rejected; use a separate empty test directory, not an implicit migration/reset. The release package and systemd example now contain only the single workbench daemon.

The socket uses mode 0600 and same-UID peer credentials on the host. This is a trusted local OS-account API, not a remote service, multi-user ACL or Telegram authorization mechanism. A selected history session can be inspected without a provider even outside the current workspace. Any UI create/prompt/answer/cancel/settings/fork/remove operation requires current VS Code workspace trust and canonical realpath containment under an open workspace root. A symlink escaping that root is rejected. Only explicit editor selection or the authorized workspace file picker can append bounded local text to the composer; tool paths, URIs and terminal references grant no file/network/terminal authority.

## Typed client and view ownership

- `workbench-protocol.ts` mirrors the public Rust enums with runtime, fail-closed boundary decoders. Business code receives domain DTOs, not an ACP-shaped facade, raw ACP JSON or blind parsed casts. Unknown fields/variants, unsafe JS integers, malformed Unicode and invalid IDs/descriptors are rejected. Rust `u64` values outside JS's safe integer range are deliberately rejected rather than rounded. This is a manually mirrored contract with real-host integration tests, not automatically generated type coverage.
- Numeric correlation IDs never repeat for the lifetime of one client; replies may arrive out of order. Mutations receive an independent generated durable operation ID exposed in a request ticket and UI operation log. Explicit programmatic replay can reuse that operation with exactly the original command. `cancel_fork` targets the **original fork operation** and has its own independent durable operation ID. Image/subscription requests reject operation IDs.
- Client quotas match each connection's 16 ordinary / 4 control / 4 query pools. Incomplete frames have a fixed 10-second deadline and 8 MiB bound, with fatal UTF-8 validation. Multiple complete frames in one socket chunk do not share an accidental aggregate cap. Socket write buffering is bounded. Explicit observer timeouts/abandonment never send cancel or resend a request; already-sent abandoned requests retain their quota until reply/disconnect, preventing an unlimited unobserved-work bypass. Long provider/fork operations have no short default observer deadline.
- A lost connection rejects observers with their operation IDs and a conservative possible-side-effect flag. The client never resends commands. The controller restores cold observation and queries unresolved operation IDs, with one reconnect task/timer and exponential retry delays from 1 to 30 seconds; successful reattachment resets the delay. Refresh also reattaches disconnected selections. Attach/receipt observers have 10-second deadlines; this does not cancel host work. Disposal stops retries. Reconnect does not mean interrupted native/tool effects were undone.
- The extension stores one validated selected-session ID per workspace/socket, alongside at most 64 operation handles without command bodies. Reload restores the selected session by cold attach, even outside the first list page, and queries original receipts without provider load or mutation replay. These are display/recovery handles, not a persisted frontend domain state.
- Selection atomically attaches a bounded recent-history page and hot view without starting an actor/worker. Explicit authorized prompt/settings mutations load before acting; no summary/new-session fallback exists.
- The Rust actor is the only session-state owner. After commit it synchronously publishes a revisioned CommitBatch. The TS session replaces hot views and applies only committed headers in consecutive revision order; duplicate revisions are ignored and gaps/disconnect trigger a fresh bounded attachment. There are no provisional rows, domain-event replay, 50 ms inspect timer or mutation-triggered full-list/full-history refreshes.
- Queries return only to their requester. A normal 500-update stream performs zero inspect queries. Create/fork/remove receipts update the local summary list; refresh and paging are explicit.

## New browser path

The new webview consumes the direct domain contract, with monotonically sequenced state messages and no old state-patch codec. It supports provider selection for new sessions, cold history selection, text prompts, cancellation (including a waiting interaction), observed model/mode choices, typed permission and multi-field forms, text/thought rows, display-only typed tool contents, plan/context/token display, native fork entry requests, exact pending-fork cancellation, operation/error display and confirmed session removal. Server validation determines whether a requested entry is a provably safe native cut: the presence of a “Fork here” button is not proof of provider support or cut safety. Uncertain/unadopted remote effects remain visible errors, not successful rollback.

Drafts remain until the matching prompt is accepted, are isolated by selected session, and are retained for at most 16 selections. Failed worker status permits an explicit next prompt/native load in the same session; no silent fresh session or history replay is introduced. Transcript uses explicit earlier/latest pages, never virtual-scroll placeholders, with at most 200 displayed entries and 1000 headers/4 MiB retained. Tool headers and content are requested explicitly; expanded text is capped at 256 KiB per item instead of indefinitely concatenating slices. UI remains a bounded view, not a second persistent history owner.

Markdown uses the existing sanitized renderer (including math) but **does not activate its old image-path markers**. Provider/tool strings use text nodes or sanitized markup; external links are inert in this initial direct-domain view. CSP forbids network connections, external image sources, frames and arbitrary scripts. Only explicit archive-read buttons request images. The extension requires full reference membership in the selected transcript, then the client verifies descriptor, canonical base64, decoded size, SHA-256 and MIME signature. The browser accepts only matching current-session references and uses Blob URLs. Four concurrent UI reads and a 32 MiB raw-byte LRU bound media work; eviction, session change and disposal revoke URLs. MIME signatures are not full decoding/sanitization; the Chromium fixture additionally proves one real valid PNG decodes for display.

## Evidence and remaining work

Tests in `test/workbench-{client,session,client-integration,controller,browser,extension,reconnect,recovery-races}.test.ts` cover wire ordering/reserves/cancellation, parser bounds, maximum 4 MiB archive response, cold resync/removal/disconnect, native fork/replay/cancel, typed form/tool/image DTOs, controller trust and command/reference authorization, canonical symlink escape rejection, browser rendering/form draft preservation and production extension CSP. Integration tests execute a real new host against the independent synthetic stdio peer in an isolated temporary HOME/storage, including observer recovery after daemon restart without provider traffic or journal writes; no account/model/Bot is involved. The default test runner builds the required binary; a missing binary fails rather than skips these tests.

`npm run test:browser` now builds and drives the **production new browser bundle** through the real new host and TS controller. Eleven Chromium checks cover creation, distinct stream groups, one-worker native fork/source preservation, typed form answers, tools, explicit archived PNG display, crash/native-load recovery, pending-form cancellation, no external browser fetch/errors and a production-extension import audit. This is not live provider/Bot acceptance, an installed VS Code host end-to-end test, a SIGKILL recovery test or long-duration soak. The old browser smoke entry has been removed with the old UI.

Current additions include explicit bounded text file attachments, full-history streaming Markdown export, turn-process folding, Thought visibility preferences, a separate Plan panel, Mermaid and code copying. Current additions also include saved workspace Diff/confirmed undo, detailed SQL statistics/pricing/model settings, manual/isolated automatic titles, bounded message copying/reuse, display preferences and the new-config Telegram wizard. See [workspace review](turn-diff.md) and [management](workbench-management.md). Remaining UI parity includes richer history navigation/search, typed context/image prompt input, thinking/Fast/config options and autonomous runs. Terminal references remain metadata rather than readable terminal output. Real Extension Host, online provider and Bot acceptance remain separate requirements; see [feature-parity.md](feature-parity.md) and [workbench-parity-execution.md](workbench-parity-execution.md). Unimplemented legacy configuration keys and the fake preview command have been removed from the manifest. The login command now explicitly shows CLI instructions rather than claiming to open an authenticated terminal. The [candidate cutover checklist](workbench-cutover.md) separates implemented features, unresolved parity, live acceptance and backup/rollback. `npm run test:extension-host` uses installed VS Code with isolated profile/root and reports BLOCKED (exit 2) without a display; its basic smoke is not the full native Diff/modal matrix. `npm run audit:workbench` checks contributed commands/configuration and actual esbuild import graphs; rebuilding richer features must not revive legacy wire dependencies. Full image decoding/sanitization, safe lifetime storage GC, native repeated-text/tool/media cut identity and provider-specific live capability matrices remain global rewrite requirements. See `docs/rewrite-verification.md` for the current full gate evidence; this frontend switch alone is not final rewrite acceptance.
