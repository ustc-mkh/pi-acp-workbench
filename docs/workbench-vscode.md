# VS Code / browser on IPC v2

The default local build bundles `src/workbench-extension.ts` and `webview/workbench-main.ts`. These use the new `WorkbenchController` / `WorkbenchSession` / `WorkbenchClient` directly, not an ACP-shaped facade or a v2-to-legacy wire adapter. The old extension/controller/wire source and old daemon crates have been removed from the production workspace. No existing service or user data was deployed, migrated or deleted.

## Local connection

Run the new host with an explicitly chosen format2 storage root:

```sh
cargo run --manifest-path rust/Cargo.toml -p pi-acp-workbenchd -- --config /absolute/path/workbench.json
```

See `examples/workbench.json`, `docs/workbench-ipc.md` and the explicit offline-only [`docs/workbench-storage.md`](workbench-storage.md) same-binary, host-lease-protected export/reset/typed Telegram GC utility. Configure **`piAcp.workbenchSocket`** to `<storage.root>/workbench.sock`; empty defaults to `~/.pi/pi-acp-workbench/workbench.sock`, matching the example root after substituting your account. Reload the extension after changing the path. There is no fallback to any old socket, service version or storage layout. An old nonempty storage directory is explicitly rejected; use a separate empty test directory, not an implicit migration/reset. The release package and systemd example now contain only the single workbench daemon.

The socket uses mode 0600 and same-UID peer credentials on the host. This is a trusted local OS-account API, not a remote service, multi-user ACL or Telegram authorization mechanism. A selected history session can be inspected without a provider even outside the current workspace. Any UI create/prompt/answer/cancel/settings/fork/remove operation requires current VS Code workspace trust and canonical realpath containment under an open workspace root. A symlink escaping that root is rejected. Only explicit editor selection can append local file text to the composer; tool paths, URIs and terminal references grant no file/network/terminal authority.

## Typed client and view ownership

- `workbench-protocol.ts` mirrors the public Rust enums with runtime, fail-closed boundary decoders. Business code receives domain DTOs, not an ACP-shaped facade, raw ACP JSON or blind parsed casts. Unknown fields/variants, unsafe JS integers, malformed Unicode and invalid IDs/descriptors are rejected. Rust `u64` values outside JS's safe integer range are deliberately rejected rather than rounded. This is a manually mirrored contract with real-host integration tests, not automatically generated type coverage.
- Numeric correlation IDs never repeat for the lifetime of one client; replies may arrive out of order. Mutations receive an independent generated durable operation ID exposed in a request ticket and UI operation log. Explicit programmatic replay can reuse that operation with exactly the original command. `cancel_fork` targets the **original fork operation** and has its own independent durable operation ID. Image/subscription requests reject operation IDs.
- Client quotas match each connection's 16 ordinary / 4 control / 4 query pools. Incomplete frames have a fixed 10-second deadline and 8 MiB bound, with fatal UTF-8 validation. Multiple complete frames in one socket chunk do not share an accidental aggregate cap. Socket write buffering is bounded. Explicit observer timeouts/abandonment never send cancel or resend a request; already-sent abandoned requests retain their quota until reply/disconnect, preventing an unlimited unobserved-work bypass. Long provider/fork operations have no short default observer deadline.
- A lost connection rejects observers with their operation IDs and a conservative possible-side-effect flag. It does not resend commands or restore subscriptions. Explicit selection creates a fresh view attachment. Reconnect does not mean interrupted native/tool effects were undone.
- Selection subscribes and cold-inspects; it does not start an actor/worker, load native history or create a durable query operation. Explicit authorized prompt/settings mutations load before acting. There is no text-summary/new-session fallback.
- The Rust actor remains the only owner of session state. Public event payloads have no revision, so the TS view **does not replay buffered lifecycle/configuration events over a newer snapshot**. It coalesces 50 ms cold inspect reads, refuses snapshot revision regression and fences outstanding reads after `resync_required`, removal or disconnection. It stops on errors instead of running a tight retry loop. Live identity-bearing rows are bounded provisional display hints (256 rows / 1 MiB), never fork authority. Confirmed snapshot rows preserve every committed delta ID and opaque group; no native timestamp is inferred.
- `inspect` and `list` now return only to their requester, without broadcasting query echoes. Explicit `load` remains a change notification. The browser integration exposed the old query-echo refresh loop; a Rust regression issues 50 ordinary queries plus a durable query and verifies zero broadcasts, then verifies explicit load still publishes.

## New browser path

The new webview consumes the direct domain contract, with monotonically sequenced state messages and no old state-patch codec. It supports provider selection for new sessions, cold history selection, text prompts, cancellation (including a waiting interaction), observed model/mode choices, typed permission and multi-field forms, text/thought rows, display-only typed tool contents, plan/context/token display, native fork entry requests, exact pending-fork cancellation, operation/error display and confirmed session removal. Server validation determines whether a requested entry is a provably safe native cut: the presence of a “Fork here” button is not proof of provider support or cut safety. Uncertain/unadopted remote effects remain visible errors, not successful rollback.

Drafts remain until the matching prompt is accepted, are isolated by selected session, and are retained for at most 16 selections. Failed worker status permits an explicit next prompt/native load in the same session; no silent fresh session or history replay is introduced. Transcript rendering windows the most recent 100 rows (explicitly expandable) and bounds visible tool calls to 300 from visible turns; provisional rows and media caches are independently bounded. UI remains a view, not a second persistent history owner.

Markdown uses the existing sanitized renderer (including math) but **does not activate its old image-path markers**. Provider/tool strings use text nodes or sanitized markup; external links are inert in this initial direct-domain view. CSP forbids network connections, external image sources, frames and arbitrary scripts. Only explicit archive-read buttons request images. The extension requires full reference membership in the selected transcript, then the client verifies descriptor, canonical base64, decoded size, SHA-256 and MIME signature. The browser accepts only a matching current-session reference and embeds a data URI; it never opens URI/path/file-ID fallbacks. Four concurrent UI reads and a 16 MiB display cache bound media work. MIME signatures are not full decoding/sanitization; the Chromium fixture additionally proves one real valid PNG decodes for display.

## Evidence and remaining work

The 44 tests in `test/workbench-{client,session,client-integration,controller,browser,extension}.test.ts` cover wire ordering/reserves/cancellation, parser bounds, maximum 4 MiB archive response, cold resync/removal/disconnect, native fork/replay/cancel, typed form/tool/image DTOs, controller trust and command/reference authorization, canonical symlink escape rejection, browser rendering/form draft preservation and production extension CSP. Four tests execute a real new host against the independent synthetic stdio peer in an isolated temporary HOME/storage; no account/model/Bot is involved. The default test runner builds the required binary; a missing binary fails rather than skips these tests.

`npm run test:browser` now builds and drives the **production new browser bundle** through the real new host and TS controller. Nine Chromium checks cover creation, distinct stream groups, one-worker native fork/source preservation, typed form answers, tools, explicit archived PNG display, crash/native-load recovery, pending-form cancellation, no external browser fetch/errors and a production-extension import audit. This is not live provider/Bot acceptance, an installed VS Code host end-to-end test, a SIGKILL recovery test or long-duration soak. The old browser smoke entry has been removed with the old UI.

Remaining UI parity includes rich history/list paging (current IPC snapshots/lists are bounded by the frame, not paginated), durable UI workflow receipts across extension reload, export/local provider login/advanced preferences/statistics/diagrams, tool/message action polish, image prompt input and tool binary archives. Unimplemented legacy configuration keys and the fake preview command have been removed from the manifest. The login command now explicitly shows CLI instructions rather than claiming to open an authenticated terminal. `npm run audit:workbench` checks contributed commands/configuration and actual esbuild import graphs; rebuilding richer features must not revive legacy wire dependencies. Full image decoding/sanitization, safe lifetime storage GC, native repeated-text/tool/media cut identity and provider-specific live capability matrices remain global rewrite requirements. See `docs/rewrite-verification.md` for the current full gate evidence; this frontend switch alone is not final rewrite acceptance.
