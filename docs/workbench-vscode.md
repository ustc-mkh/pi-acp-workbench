# VS Code / browser on IPC v3

The default local build bundles `src/workbench-extension.ts` and `webview/workbench-main.ts`. These use the new `WorkbenchController` / `WorkbenchSession` / `WorkbenchClient` directly, not an ACP-shaped facade or a legacy wire adapter. The old extension/controller/wire source and old daemon crates have been removed from the production workspace. No existing service or user data was deployed, migrated or deleted.

## Local connection

Run the new host with an explicitly chosen format3 storage root:

```sh
cargo run --manifest-path rust/Cargo.toml -p pi-acp-workbenchd -- --config /absolute/path/workbench.json
```

See `examples/workbench.json`, `docs/workbench-ipc.md` and the explicit offline-only [`docs/workbench-storage.md`](workbench-storage.md) same-binary, host-lease-protected export/reset/typed Telegram GC utility. Configure **`piAcp.workbenchSocket`** to `<storage.root>/workbench.sock`; empty defaults to `~/.pi/pi-acp-workbench/workbench.sock`, matching the example root after substituting your account. Reload the extension after changing the path. There is no fallback to any old socket, service version or storage layout. An old nonempty storage directory is explicitly rejected; use a separate empty test directory, not an implicit migration/reset. The release package and systemd example now contain only the single workbench daemon.

The socket uses mode 0600 and same-UID peer credentials on the host. This is a trusted local OS-account API, not a remote service, multi-user ACL or Telegram authorization mechanism. A selected history session can be inspected without a provider even outside the current workspace. Any UI create/prompt/answer/cancel/settings/fork/remove operation requires current VS Code workspace trust and canonical realpath containment under an open workspace root. A symlink escaping that root is rejected. Only explicit editor selection or the authorized workspace file picker can append bounded local text to the composer; tool paths, URIs and terminal references grant no file/network/terminal authority.

## Typed client and view ownership

- `workbench-protocol.ts` mirrors the public Rust enums with runtime, fail-closed boundary decoders. Business code receives domain DTOs, not an ACP-shaped facade, raw ACP JSON or blind parsed casts. Unknown fields/variants, unsafe JS integers, malformed Unicode and invalid IDs/descriptors are rejected. Rust `u64` values outside JS's safe integer range are deliberately rejected rather than rounded. This is a manually mirrored contract with real-host integration tests, not automatically generated type coverage.
- Numeric correlation IDs never repeat for the lifetime of one client; replies may arrive out of order. Mutations receive an independent generated durable operation ID exposed in a request ticket and UI operation log. Explicit programmatic replay can reuse that operation with exactly the original command. `cancel_fork` targets the **original fork operation** and has its own independent durable operation ID. Image/subscription requests reject operation IDs.
- Client quotas match each connection's 16 ordinary / 4 control / 4 query pools. Incomplete frames have a fixed 10-second deadline and 8 MiB bound, with fatal UTF-8 validation. Multiple complete frames in one socket chunk do not share an accidental aggregate cap. Socket write buffering is bounded. Explicit observer timeouts/abandonment never send cancel or resend a request; already-sent abandoned requests retain their quota until reply/disconnect, preventing an unlimited unobserved-work bypass. Long provider/fork operations have no short default observer deadline.
- A lost connection rejects observers with their operation IDs and a conservative possible-side-effect flag. The client never resends commands. The controller restores cold observation and queries unresolved operation IDs, with one reconnect task/timer and exponential retry delays from 1 to 30 seconds; successful reattachment resets the delay. Refresh also reattaches disconnected selections. Attach/receipt observers have 10-second deadlines; this does not cancel host work. Disposal stops retries. Reconnect does not mean interrupted native/tool effects were undone.
- The extension stores one validated selected-session ID per workspace/socket, alongside at most 64 operation handles without command bodies. Reload restores the selected session by cold attach, even outside the first list page, and queries original receipts without provider load or mutation replay. These are display/recovery handles, not a persisted frontend domain state.
- Selection atomically attaches a bounded recent-history page and hot view without starting an actor/worker. Explicit authorized prompt/settings mutations load before acting; no summary/new-session fallback exists.
- The Rust actor is the only session-state owner. After commit it synchronously publishes a revisioned CommitBatch. The TS session replaces hot views and applies only committed headers in consecutive revision order; duplicate revisions are ignored and gaps/disconnect trigger a fresh bounded attachment. There are no provisional rows, domain-event replay, 50 ms inspect timer or mutation-triggered full-list/full-history refreshes.
- Queries return only to their requester. A normal 500-update stream performs zero inspect queries. Create/fork/remove receipts update the local summary list; refresh and paging are explicit.

## New browser path

The new webview consumes the direct domain contract, with monotonically sequenced state messages and no old state-patch codec. It supports provider selection for new sessions, cold history selection, text prompts, cancellation (including a waiting interaction), observed model/mode choices, typed permission and multi-field forms, text/thought rows, display-only typed tool contents, plan/context/token display, native fork entry requests, exact pending-fork cancellation, operation/error display and confirmed session removal. Server validation determines whether a requested entry is a provably safe native cut: the presence of a “Fork here” button is not proof of provider support or cut safety. Uncertain/unadopted remote effects remain visible errors, not successful rollback.

Drafts remain until the original operation and submitted draft generation are accepted; even editing back to identical text cannot let an old acceptance clear a newer draft. Text/context drafts are isolated by selected session and retained for at most 16 selections. Typed ordered text/context/image parts replace attachment-path concatenation. Explicit file/editor context retains its source and identity in immutable history; ACP uses embedded text resources when negotiated, otherwise source-labelled text blocks. Image selection/paste provides preview/removal, at most one image per prompt and four unsent image drafts (4 MiB each); unsent image bytes are memory-only and discarded on reload. The daemon fully decodes static PNG/JPEG/WebP input under 8192-dimension/16-million-pixel/64-MiB decoder limits, rejects animation/corruption, then re-encodes PNG (also capped at 4 MiB) before acceptance/archive/provider dispatch. Two global decode jobs bound concurrent blocking work. Negotiated image support is checked before durable acceptance; unsupported peers report an error and retain the draft. No remote URL/path fallback exists. Failed worker status permits an explicit next prompt/native load in the same session; no silent fresh session or history replay is introduced. Selecting or reattaching a session shows the latest 3 complete turns. “加载更早消息（20 轮）” prepends 20 complete turns using bounded 200-header high-water pages; a long turn is never treated as a fragment-count page. Live output continues while earlier turns are expanded. The bottom arrow is the only return-to-latest control and reloads the newest 3 turns when needed. The view is bounded to 20,000 headers / 8 MiB; live trimming removes whole oldest turns, while an individually oversized turn reports the display limit instead of dropping its prefix. Archived message text is read in 64 KiB slices, verified against its full SHA-256 and joined with adjacent fragments before Markdown/LaTeX rendering (2 MiB per archived item, 8 MiB total cache). Larger or unreadable items retain explicit archive/export controls. Tools and images remain explicit reads; browsing never starts a provider or replays input. UI remains a bounded view, not a second persistent history owner.

Markdown uses the existing sanitized renderer (including math) but **does not activate its old image-path markers**. Provider/tool strings use text nodes or sanitized markup; explicit link clicks request a host modal showing the normalized destination (including punycode), with Open/Copy/Cancel. Only credential-free HTTP(S) and mailto are allowed; command/javascript/file/relative links are rejected, and workspace trust is checked again after the modal. CSP forbids network connections, external image sources, frames and arbitrary scripts. Only explicit archive-read buttons request images. The extension requires full reference membership in the selected transcript, then the client verifies descriptor, canonical base64, decoded size, SHA-256 and MIME signature. The browser accepts only matching current-session references and uses Blob URLs. Four concurrent UI reads and a 32 MiB raw-byte LRU bound media work; eviction, session change and disposal revoke URLs. MIME signatures are not full decoding/sanitization; the Chromium fixture additionally proves one real valid PNG decodes for display.

## Pi autonomous runs

Negotiated Pi workbench v1 peers use explicit `pi-workbench-run` start/finish and `pi-workbench-live` identities. A wake gets its own durable turn, history, permissions, usage and completion delivery; unlabelled idle text is not a wake. User prompts are rejected while that turn is busy (no steering/follow-up). If a wake wins the final provider submission window, the accepted input remains in history with an explicit rejection marker, not as executed input. Pi drafts wait for evidence of normal output/settlement before clearing; a rejection preserves the current draft and never overwrites newer edits. Stop joins the worker and fences late events.

The bridge reports starts after execution may already have begun. Autonomous workspace Diff is therefore explicitly **unavailable**, never a synthetic before-snapshot. The existing worker-lifetime workspace gate still prevents concurrent undo. Stopping an active Pi autonomous run first requests native cancellation and retains the same worker on confirmed settlement; after five seconds without settlement the host fences and joins the worker. Explicit worker release always stops and joins it. Idle workers, including those capable of future autonomous wakeups, remain subject to the documented capacity and one/four-day retention policy, just as in v1.0.0. Retirement does not persist native extension timers or automatically resume future wakeups. Cold attach/reload does not start or resume the provider. Real online Pi acceptance remains a release-validation task.

## Verification and development scope

Tests in `test/workbench-{client,session,client-integration,controller,browser,extension,reconnect,recovery-races}.test.ts` cover wire ordering/reserves/cancellation, parser bounds, maximum 4 MiB archive response, cold resync/removal/disconnect, native fork/replay/cancel, typed form/tool/image DTOs, controller trust and command/reference authorization, canonical symlink escape rejection, browser rendering/form draft preservation and production extension CSP. Integration tests execute a real new host against the independent synthetic stdio peer in an isolated temporary HOME/storage, including observer recovery after daemon restart without provider traffic or journal writes; no account/model/Bot is involved. The default test runner builds the required binary; a missing binary fails rather than skips these tests.

`npm run test:browser` now builds and drives the **production new browser bundle** through the real new host and TS controller. Chromium checks cover creation, distinct stream groups, one-worker native fork/source preservation, typed form answers, tools, explicit archived PNG display, crash/native-load recovery, pending-form cancellation, no external browser fetch/errors and a production-extension import audit. This is not live provider/Bot acceptance, an installed VS Code host end-to-end test, a SIGKILL recovery test or long-duration soak. The old browser smoke entry has been removed with the old UI.

The UI exposes the provider's bounded typed select settings (including separate Pi Thinking/Fast when actually offered), retaining IDs, categories, choices and observed values. Settings do not rebuild on unrelated stream deltas. Generic settings explicitly discover/recover a native peer before first-task configuration, prepare a durable restore baseline, and settle only on provider-observed values. Failed/unknown attempts never seed new-session preferences or auto-resend on reload. Existing session choices take priority; new sessions inherit recent successful model/thinking by harness, never Fast or context authorization. Fast remains native/session-local; native fork/load capability still requires real-provider validation.

The UI provides bounded text/image attachments, full-history Markdown export, process/Thought preferences, a separate Plan panel, Mermaid, copying/reuse and display preferences. Workspace review and management are documented in [Diff/undo](turn-diff.md) and [usage/model management](workbench-management.md). Terminal references explicitly say metadata-only: this client advertises `terminal: false`, so no negotiated terminal output port exists and no stdout/stderr/exit status is invented or fetched from paths. Native terminal execution/output support is not claimed. Login explicitly confirms built-in Pi (`pi`, then `/login`), Codex (`codex login`) or Claude (`claude auth login`) profiles before opening a native terminal. No model-supplied/custom worker command or credentials are passed. Missing CLI/auth availability remains a native environment error.

Logical messages join only adjacent fragments with a nonempty provider message ID, the same turn/role, consecutive sequence and no image boundary. Missing IDs never imply a merge. Desktop/copy/export share `workbench-messages.ts`; Telegram turn streaming uses the same predicate. Entries stay immutable. Copy scans cold pages across both message boundaries (1 MiB clipboard limit); export spools page headers to disk, streams verified archive bodies and carries message identity across pages. The native fork button targets the last committed fragment, not a guessed provider cut.

The display incrementally appends fragments, coalesces state updates per animation frame and reconciles keyed turn/message DOM in place. Streaming paints are coalesced at an 80 ms interval; each paint parses the complete received Markdown within a 256 KiB display budget. Completed inline syntax, lists, tables and code fences render during the turn rather than waiting for a length checkpoint. Completion, session switches and local controls paint immediately. Only text beyond the display budget uses a bounded plain-text remainder. Oversized text explicitly directs the user to full copy/export. Thought/process folds preserve explicit user choices and otherwise close when the turn finishes. The Plan card has an approximately five-item internal scroll area. Session list presets are 4/10/16 rows; selection/refresh/send do not dismiss it. Composer resize supports pointer and keyboard controls with a persisted height. Slash completion shows only provider-declared commands, supports Up/Down/Tab/Enter/Escape and leaves IME Enter alone. Empty catalogues show no invented commands.

Architecture constraints are described in the [architecture guide](workbench-next-rewrite-plan.md); historical acceptance scope is recorded in the [P6 matrix](workbench-p6-validation.md). `npm run test:extension-host` uses installed VS Code with an isolated profile/root and reports BLOCKED (exit 2) without a display; the basic smoke is not the complete Diff/modal/trust/clipboard matrix. `npm run audit:workbench` checks contributed commands/configuration and source/runtime import graphs. Rebuilding features must not revive legacy wire dependencies. Deployment and whole-combination rollback follow the [cutover checklist](workbench-cutover.md).

### Model defaults, overrides and estimated cost

Model settings read price and context metadata from Pi's local model registry (including known models without a configured channel login); refreshing metadata does not request model inference. Channel prefixes, case, whitespace, hyphens and underscores are ignored when matching the model portion of an ID: `openai/GPT-6.1 Sol` and `wwzz/gpt-6.1-sol` share defaults. Decimal versions, dates and variant suffixes remain significant. Known official provider defaults take precedence over channel placeholders; unavailable metadata remains unknown instead of inventing prices or context limits.

Opening either **模型设置** or **用量统计** refreshes the shared profile metadata automatically before reading settings/statistics. No selected session is required; active conversations continue independently. The matching adapter reads the local registry in a temporary process with native session persistence and tools disabled, then exits. Concurrent page requests share one refresh; pagination and session selection only read saved data. Failed refreshes show saved data with a status message. Custom prices and context overrides are preserved.

Explicit user prices, context overrides, visibility and a per-model price multiplier remain specific to that channel/model. Defaults and overrides are stored separately, so refreshing Pi metadata or restarting the host preserves user values. The multiplier defaults to 1 and accepts finite values from 0 to 1,000,000. Statistics estimate each token category at its configured/default USD-per-million price, multiply their sum by this multiplier, and keep missing usage or prices marked as missing. Estimates use current settings, including when viewing earlier usage; they do not change provider-reported usage or invoices.

Each model has one **保存** action for prices, multiplier, visibility and context. Clearing all four prices selects the defaults; clearing context restores Pi's default. **恢复默认** clears the model's explicit overrides and resets its multiplier to 1. Other Agents may display matched defaults but cannot edit Pi context. Updating an existing validated 2.0.x root adds the model-setting columns and context projection tables; the history, operation journal and Telegram state are retained. Upgrade client, host and Pi adapter together and keep the usual stopped-root backup.

### Shared Pi context persistence

The shared daemon's SQLite database is the authority for desired model settings across workspaces connected to that daemon. A context save commits the desired value, a monotonically increasing revision and a pending intent together with the other model settings. The daemon serializes context projection for its configured Pi profile. It then asks the matching adapter to merge that revision into the profile's `models.json`, refresh Pi's local registry and confirm the applied value. SQLite marks the exact revision applied only after that acknowledgement. Prices and multipliers stay in SQLite; Pi's context override must also exist in `models.json` so native model selection and subsequent Pi processes see it.

The adapter holds a cross-process lock on the canonical `models.json` target through read/merge/atomic replacement, registry refresh and acknowledgement. Directory aliases and file symlinks use the same target lock. It preserves unrelated provider/model fields. The adjacent `models.json.workbench-context.json` checkpoint records the owning data root, revision and prepared/applied state. Older revisions, conflicting same-revision values and another data root attempting to manage the same profile are rejected. Use a dedicated, stable Pi profile for each Workbench data root; changing or restoring a data-root path requires checking its profile ownership before saving new settings.

SQLite and a JSON file are separate durable stores, not one atomic transaction. If a worker stops after publishing the file but before acknowledging it, the pending SQLite intent survives. The next explicit Pi discovery, refresh or prompt reconciles it before new input is dispatched; cold history queries and daemon startup do not start a provider just to recover settings. Retrying the same prepared revision refreshes and confirms the existing value without rewriting it. A failed save remains visibly pending, with an error when available. After checking an external-edit conflict, explicitly saving again creates a new revision. Recovery never replays a model prompt.

Back up the stopped daemon root and the associated Pi profile together, including `models.json` and its `.workbench-context.json` checkpoint. Do not independently delete the checkpoint or restore an older database over a newer profile: the revision fence may correctly reject that combination. The lock coordinates Workbench writers. Programs that ignore that lock can still edit the file; before-replacement and after-refresh checks detect observed conflicts, but cannot provide SQLite-style isolation against arbitrary external writers. Stop other editors when deliberately changing the same model's context outside Workbench.

For an opt-in offline integration check, build the current extension and daemon, then run `PI_OFFLINE_PI_CLI=/absolute/path/to/pi/dist/bundle/cli.js node scripts/workbench-context-offline.mjs`. This uses an isolated HOME/profile, dummy local provider metadata and a Node network-denial assertion hook; it makes no model prompt. It checks two workspaces, actual Pi registry refresh, daemon/Pi restart and restoring the default. The report is `.test-results/context-offline.json`; failed fixture roots are retained for diagnosis.
