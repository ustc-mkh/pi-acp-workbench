# VS Code 使用

安装和 socket 配置见[安装与部署](workbench-release.md)。扩展仅在受信任的文件系统工作区启用。

## 对话与输入

点击活动栏 **Pi Agent** 或运行 **Pi: Open Chat**。新建会话时选择 Agent；模型和 thinking/mode 控件只展示 provider 实际提供的选项。新会话继承该 Agent 最近成功使用的模型和 thinking；已有会话保留自身设置，Fast 不作为全局默认。

- 输入区支持 provider 声明的斜杠命令，使用方向键、Tab/Enter 选择，Escape 关闭；输入法确认不会误发送。
- **Pi: Add Selection to Chat**（`Ctrl+Alt+P`，macOS 为 `Cmd+Alt+P`）添加选区，也可选择文本文件加入上下文。
- 图片可粘贴，或右键“上下文”按钮选择。每次输入最多一张、原始大小最多 4 MiB；未发送图片仅保存在内存，重载会丢失。输入支持静态 PNG/JPEG/WebP，由宿主解码校验并重新编码后发送。
- 草稿按会话保留；接受回执确认后清理对应草稿。失败或结果未确认时保留，新编辑的内容不会被旧回执覆盖。
- 授权、选择、确认和文本表单直接显示在对话中。停止当前任务不会撤销已经发生的副作用。

消息支持 Markdown、代码、公式和 Mermaid。思考与工具调用可折叠，待办独立展示；会话列表高度可选 4/10/16 行，输入区高度可调整。外链由宿主确认后打开，页面不会自动读取消息中的文件路径或远程图片。终端引用仅作元数据展示，当前没有终端输出流。

## 历史与会话

打开会话显示最近 3 个完整回合，“加载更早消息”每次补充最多 20 轮并保持滚动位置。浏览历史不启动 provider；流式输出继续接收。归档正文进入可见区域后批量加载、校验并渲染，超大正文保留分片读取和导出入口。

历史列表支持搜索、重命名、删除和释放 worker。共享历史清空先显示预览，每批最多 10 个会话并再次确认。删除不清理 provider 原生历史或已发生的费用事实。

每条消息可复制；用户文本可追加为当前草稿。复制上限为 1 MiB，完整 Markdown 导出读取全部已提交历史、按时间顺序写出，图片以归档描述记录。**Fork here** 请求 provider 原生分支，只有可证明的原生切点和支持该能力的 adapter 才会成功。

工作区变更自动显示在轮次下方，详见 [Diff 与撤回](turn-diff.md)。模型设置、统计和命名见[模型与用量](workbench-management.md)。

## 后台运行与资源释放

关闭页面不取消已接受任务。断线后自动恢复观察并查询原操作回执，不重新发送输入；打开历史或重连也不自动恢复后台定时器。

默认最多驻留 16 个 provider worker，可通过 `sessions.max_workers` 调整。最近使用的 8 个驻留会话保留 4 天，其他保留 1 天，按最后一次被接受的用户消息计时；尚无用户输入的 worker 按创建时间计时。浏览历史、设置和自主轮次不续期。

超出容量或到期时回收空闲 worker；活动任务、交互、配置、分支及标题工作受到保护。列表编号以绿色/黄色标示 4 天/1 天驻留，电源按钮可手动释放；忙碌时需确认停止。释放保留历史与原生会话，下次明确使用时恢复。

配套 Pi adapter 支持独立自主后台轮次，具有自身历史、授权、用量和完成通知。此时普通输入不作为 steering/follow-up。停止先请求 Pi 取消，确认结束后保留 worker；5 秒未结束则终止并等待退出。自主轮次没有完整轮前快照，因此 Diff 显示不可用。释放 worker 或宿主重启后，不自动恢复扩展定时唤醒。

## 实现

`src/workbench-client.ts` 负责 IPC，`workbench-session.ts` 维护有界显示视图，`workbench-controller.ts` 处理工作流和授权。`webview/workbench-main.ts` 渲染页面；流式绘制按 80 ms 合并，使用稳定消息键复用 DOM。领域状态和历史以宿主为准，协议见 [IPC v3](workbench-ipc.md)。
