# 经典界面对齐

本次以 v1.0.0 标签及安装前保存的原版扩展为视觉参考，恢复原版信息层级；继续使用 2.x 的 v3 宿主，旧数据无需重新导入。

- 顶部保留 Harness、历史、导出、模型设置、用量与新对话，历史默认收起。
- 对话占据主体，消息保持 Markdown、代码、公式与图片渲染；思考和工具调用折叠展示。
- 输入区固定底部，恢复原版模型下拉样式、上下文圆环、发送/停止、草稿、图片和上下文附件。
- 模型与统计独立打开，返回后继续原草稿。诊断、登录及低频操作移入会话菜单。
- 授权提示、待办、原生分支、工作区变更及确认撤回继续使用现有安全流程。切换 Harness 不会终止后台任务或自动发送输入。

验证包括完整 TypeScript 回归、真实 Chromium 的 320/460/900 像素及明暗主题布局、连续 1000 片段渲染、隔离 VS Code 原生输入/授权/撤回/重载，以及安装包的原生 UI 与 Workspace Trust 检查。布局截图由 `scripts/workbench-browser-smoke.mjs` 输出到 `test-results/workbench-browser/`；测试使用隔离模拟 Agent，不访问日常 Bot 或真实模型账号。

本地安装后，在 VS Code 执行 **Developer: Reload Window** 加载新的页面资源。无需重启日常宿主或 Telegram 服务。

## 2.0.5 严格对照

使用真实 v1.0.0 扩展的 `dist` 作为基线，而不是手工重绘一份“原版”。执行：

```sh
node scripts/workbench-ui-parity.mjs --baseline /path/to/v1-extension/dist
```

脚本在相同内容、字体、主题和 viewport 下生成 40 张截图，覆盖空白、对话、历史、模型分组、展开模型、统计、执行过程、生成中、待办与授权。空白/对话页设置自动门禁：工具栏、输入区和消息几何偏差 <= 2px，逐像素最大 RGB 差异超过 32 的像素占比 < 1%。所有场景检查浏览器错误。结果位于 `.test-results/ui-parity/report.json`；其他页面同样保留原版/新版成对截图用于人工复核，不将全部页面宣称为逐像素一致。

保留的新版行为：共享历史删除需要确认；模型价格和 context 是独立、有回执的配置操作；统计日期使用 UTC、缺失值保持显式提示。图片可粘贴，或右键“上下文”按钮选择文件。窄侧栏下，右键 Harness 打开会话选项。原来未手动调整的 100px 输入区默认值迁回原版 80px，其他自定义高度保留。

## 日常体验修复（2.0.7）

- 输入取得宿主的接受回执后，立即清空输入框，包括 Pi 尚未开始输出的思考阶段。发送失败或结果未确认时保留草稿；Pi 因后台任务拒收时恢复原草稿，若已经输入了新草稿则保留新内容，旧输入仍可从消息记录重用，不自动重发。
- 明确新建会话时自动加载模型与设置，并应用该 Agent 上一次使用的模型和 thinking。初始化期间可以输入草稿，待就绪后发送；打开历史会话、重连页面不会自动启动模型或任务。
- 全局偏好继续保存在宿主数据库，按 Agent 分开，重启后仍可继承。仅查看旧会话不覆盖偏好；真实用户任务使用的模型与 thinking、成功的明确设置操作才更新偏好。
- 错误提示右侧可以关闭；相同错误的普通刷新保持关闭，新操作失败仍会重新提示。

### 会话保留策略

默认最多同时保留 16 个 provider worker（宿主配置 `sessions.max_workers` 可以指定更低或更高的资源上限）。按**用户最后一次被接受的消息**排序，不按打开、查看、发现模型或设置的时间排序。

最近运行过的 8 个驻留会话，从最后一次用户消息起保留 4 天；其他驻留会话保留 1 天。尚无用户消息的新会话，从 worker 建立起按 1 天计算。用户输入的时间和顺序从现有持久化任务记录读取，重新加载或宿主重启不会将浏览操作当成新输入续期。原生分支继承的历史及后台自主运行不算新的用户输入。

后台每分钟检查过期会话，超过数量上限时则立即尝试释放最早的空闲会话。生成中、等待授权、配置变更尚未完成、原生分支或标题生成持有保护的会话不强制回收；若全部受保护，新任务仍会明确报告容量不足。回收前由会话 owner 串行确认空闲并隔离旧 worker 的迟到事件，物理进程退出并 join 后才复用名额。

释放 worker 不删除会话、消息、操作回执或原生历史；下次明确使用时恢复原生会话，不重放旧输入。后台自主唤醒只在 worker 驻留期间继续等待，释放后需要明确重新使用会话。

## Diff、留存标记与 Telegram 对齐（2.0.7）

- 变更卡片自动显示，移除“查看工作区变更”按钮。标题、全部修改、逐文件展开、总 Diff、整轮撤回及底部说明按原版层级排列；不完整捕获禁用整轮撤回。右键“撤回本轮修改”仍可进入高级逐文件选择，保留原有预检与确认。
- 历史滚动到旧回合时自动读取该回合 Diff。读取并发上限为 2，缓存最多 16 个回合；只读取已确认的当前会话历史，不启动任务或重放用户输入。文件内容仍按需分片加载。
- 编号按宿主实际驻留状态显示：4 天绿色、1 天黄色、未驻留默认色。删除旁新增电源形状的释放按钮；释放保留全部历史与原生会话。正在运行或等待交互时，需要明确再次确认停止；宿主检查真实状态和工作区权限后才执行。
- Telegram 的 `/new` 在原话题中使用时也创建独立新话题，不覆盖旧绑定。桌面新会话在唯一已授权且验证为 forum 的群中自动镜像话题；标题使用 `#编号 · 会话标题`，改名后同步。多个 forum 或无法确认目标时不擅自选择，继续使用明确同步或既有绑定。
- 打开已绑定会话返回其原话题，不抢占调用方绑定。话题尚未建立时保留待投递输出；创建结果不确定时保留原始回执，不盲目重建或重复发送。标题循环改名及重启不重复建话题。

留存字段需要配套更新宿主和扩展；连接不提供该字段的旧宿主时显示默认颜色并禁用手动释放。该记录描述源码验收范围；正式发布与安装须使用配套版本、备份并核对制品。

本轮验证记录及散列：`.test-results/ui-alignment/classic-followup-summary.json`。截图 `test-results/workbench-browser/classic-diff-reference.png` 使用与用户参考相同的四文件展示数据，仅用于检查样式，不代表修改了那些文件。功能检查使用真实隔离宿主、模拟 Agent 和本地 Telegram HTTP 服务。

## Pi 提问与后台运行的 1.0 对照

- `select`、`confirm`、`input`、`editor` 恢复“Pi · 等待你的回答”专用卡片，保留原始选项、说明、输入提示、编辑器预填内容和 3/6 行输入区。取消与空文本提交分别传递；普通状态刷新不覆盖正在编辑的回答。文本仍使用标准 elicitation 传值，展示提示随有类型的交互保存，不再借用 permission 的私有回答字段。
- 等待回答时完整渲染当前消息的 Markdown，继续显示用户消息操作，隐藏正在生成的助手消息操作。提问卡片出现后，处于跟随模式的对话继续滚动到底部。
- Pi 后台自主运行的“停止”先取消当前运行，正常结束后保留同一个 worker 及未来扩展唤醒；5 秒未结束时，使用现有持久取消围栏并终止、join worker。历史列表的电源按钮仍明确释放 worker，独立于“停止当前运行”。后台开始不再插入伪装成助手回答的内部诊断文字。
- v1.0.0 同样按容量和空闲期限回收 worker，并不保证后台计时器跨 worker 释放或宿主重启自动恢复。当前继续保留这项边界；不新增原版没有的通用后台任务管理面板。
- `scripts/workbench-ui-parity.mjs` 对照真实 v1.0.0 源码构建的页面，覆盖四种提问卡片的 320/460px 截图。功能验证使用隔离 ACP peer；不将模拟结果表述为真实在线 Pi 扩展验收。
