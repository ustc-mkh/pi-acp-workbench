## Chronological implementation notes (historical intermediate states)

Earlier "remaining" statements and counts in this chronological section describe that checkpoint, not current TODOs. The latest matrix/logs above and final local acceptance below supersede them. They are retained as provenance, including failures and withdrawn safety claims, not as evidence that an old compatibility path is still shipped.

- IDs, model/mode catalogue values, workspace paths and prompts now validate serde inputs as well as explicit constructors. Workspace paths are lexically normalized and absolute; filesystem authorization/canonicalization remains an adapter responsibility.
- Interaction definitions and answers are typed (permissions, text, choice/multiselect, boolean, integer, decline/cancel), validated before consumption, and checked against an explicit clock for expiry. Invalid/duplicate answers cannot consume a pending interaction.
- Pure domain reducer covers busy admission, stale-turn events, prompt transcript, plan/usage, configuration changes, cancel and crash interaction cleanup. Actor now uses this reducer.
- Registry forwards session commands without awaiting their replies; bounded admission has explicit backpressure tests. Shutdown joins actor tasks; duplicate loads retain the existing owner.
- State commits happen before event publication; failed saves leave the owned state unchanged. History uses durable atomic replacement and validates version, identity, revision and checksum. Removal drains the actor before unlinking history.
- Snapshot/inspect includes the full domain projection. Cold listing does not start actors or workers. Sixteen sessions accept 100 concurrent state commands in a regression test; this is not the planned 16-worker soak test.
- JSON-RPC codec now uses standard 2.0 envelopes, supports numeric/string IDs, preserves explicit null results and rejects ambiguous envelopes. The shared ACP corpus round-trips through this boundary.
- Worker lifecycle now has owned semaphore capacity, monotonically increasing launch epochs, bounded command/frame/request limits, request correlation/timeouts and a cancellation-aware supervised I/O loop. Stop joins the supervisor task; process-group guards clean descendants even after task abort. Tests cover failed-spawn capacity recovery, replacement epochs, EOF rejection, standard stdio requests and TERM-resistant descendants.
- SessionActor now accepts epoch-bound worker messages; obsolete attachments and late events from replaced workers are fenced. App routes real worker callbacks through this API.
- Typed ACP initialize/new/load/prompt/cancel APIs and standard content/update DTOs replace scaffold wire shapes. Known malformed updates are errors; unknown updates/content have explicit boundary handling. Context occupancy is separate from billing token totals.
- App uses a supervised reusable adapter per session, not raw JSON construction. Integration tests exercise consecutive turns, permission/text/choice/multiselect answers, decline/cancel, plan status, token usage, cancellation/replacement, crash/recovery and daemon restart without history replay. Native provider session IDs are persisted and loaded rather than silently replaced. Tool partial updates preserve prior fields and are scoped to a turn.
- Sixteen real synthetic ACP child processes can hold independent permission interactions concurrently and are joined on shutdown; interrupted persisted interactions resolve on restart. This is a bounded regression scenario, not a long-duration soak.
- Normal shutdown commits cancellation inside SessionActor and reports final-state persistence failures through `shutdown_checked`; abrupt restart recovery is tested with an in-flight snapshot. Worker Send/notify/respond now await a flushed frame acknowledgement, and adapter cancellation waits for those writes plus a bounded provider completion interval before stop/join. Cancellation never starts a previously unpolled prompt merely to wait for it. Shutdown cancels adapters concurrently; cancelled worker epochs are invalidated immediately. A real-process trace contract proves cancel and cancelled interaction responses reach the peer before exit. The later two-phase cancellation and configuration-reconciliation changes below add explicit durable intermediate states and failure-order regressions; sustained failure/soak review remains.
- Prompt RPCs no longer inherit the short control-request deadline, so long tasks and human answers are not aborted after 30 seconds. Unsupported/nested form schemas produce an explicit decline on the wire without disconnecting.
- Provider model/mode catalogues are typed and persisted, including flat/grouped select DTOs and legacy model/mode descriptors. Live configuration calls the provider before committing the local preference; each prompt reapplies its persisted desired configuration. Invalid offered values are rejected. Remaining provider catalogue notification and extension coverage must still be expanded.
- External IPC v2 now dispatches directly to the new runtime and is bound by the production entrypoint. It cannot deserialize internal Agent/worker commands, limits frames/connections/subscriptions, checks UID/socket permissions and removes only its own socket inode. SIGTERM and listener exit supervise cleanup. Protocol and migration boundaries are documented in `docs/workbench-ipc.md`.
- Storage now has a host-wide exclusive lease and format marker. Nonempty unversioned storage, corrupt/incompatible markers and a second host fail closed without deleting user data. Explicit unlock avoids fork/exec descriptor-inheritance races.
- Journal now has typed operation IDs/fingerprints and Started/Completed/Failed/Tombstone records. Side effects follow durable Started; receipts reference separate checksummed immutable results. Interrupted operations cannot rerun; conflicting IDs, corrupt/missing/mismatched payloads and expired results fail closed. Result GC retains tombstones. Host mutating commands use this journal; IPC `operation` IDs preserve original receipts across reconnect/restart, tested against real processes.

SessionActor commits delivery intent together with session state in the checksummed history snapshot. Removal transfers every intent to outbox before deleting history, and archived payloads survive deletion. Tests cover the actual app + ACP output → commit → restart → projection → removal → ack path without rerunning the agent. Images are not integrated yet.
